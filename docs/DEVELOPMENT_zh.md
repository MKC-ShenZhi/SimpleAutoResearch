[English](DEVELOPMENT.md) · [开始使用](USAGE_zh.md) · [配置参考](CONFIG_REFERENCE_zh.md)

本文面向贡献者：先找到改动的归属，再验证行为与兼容性。

## 准备开发环境

使用 Python 3.12+、Git、uv 和 ripgrep。在仓库根目录执行：

```bash
uv sync --locked --extra examples
uv run simple-ar --help
uv run simple-ar-checks --list
```

`examples` 额外依赖用于部分执行案例。模型密钥不是离线检查的前提；
真实模型调用和联网任务需另行配置与授权。
共用科研环境需要保留额外包时，可用 `uv sync --inexact --extra examples`。
不要把待处理项目的大型依赖或 benchmark 环境装进框架环境。

## 理解两类入口

技术 greenfield 可以从空工作区或挂载的源码脚手架（`copy`/`sparse_copy`）出发，复用同一原生准备和反馈所有者。结构化科学任务仍保留测量协议；规划和派发共用 `task_plan.action_binding`，但身份映射不授予权限，也不把验证器通过当作科学测量。已有动作和账本保留原语义。

当前实现有两类实际消费者，不应把它们混称为一套已完成迁移的流程：

```text
普通目标 / 已迁移精确请求
  → ToolApplication → CommonToolGateway → 专业工具

剩余科学协议 / 已保存结构化会话
  → ResearchApplication → 类型化能力

共享：SessionController、产物记录、预算与执行基础
```

普通入口根据目标和观察选择行动；任务名称不是执行权限。
结构化表格、材料报告及调研简报输入现投射为共同所有者的冻结专业合同；部分研究/执行混合合同与历史结构化续接仍由ResearchApplication承接。它不是原生任务失败后的静默回退。

`ToolApplication.supply(supply_id=..., reason=..., changes=..., resource_allowances=...)`是调用方补齐原生任务缺失合同的操作，不是模型工具或新运行时。与创建共用前置校验，原actions日志保存先前配置、补齐中断意图和最终参数；原账本按稳定ID只授权一次。补齐中断期间阻止执行，不改旧观察和消耗。新增测量义务后报告证据由材料升级为实测，旧材料报告不能冒充满足。已有冻结合同替换及历史续接仍用原协议。

`request_execution_confirmation()`经同一个source协议所有者冻结已声明科学合同；调用方提案在`inputs/caller-protocols`，不是虚构attempt或生成设计。声明前须经创建或supply保存确认义务（`research_policy.require_design=true`）；接受不授予进程权限，也不取消原命令队列。实际设计与调用方协议共享原件/响应核验，但真实设计仍必须保留原设计及来源记录。协议回复和实际进程审批是不同授权。

原生测量可显式选择已完成的实施回执，而非全局当前候选。实施所有者核实际准备、独立验证器及共享进程账目；科学执行用该候选解释器/环境并保留真实来源引用。原文件字节受约束，新增源码或依赖声明需要验证。物理验证器事实核查归CodeTask，与中断恢复共享，不在消费者分别实现。正式测量与验证是两个独立物理调用，普通benchmark可以使用同一argv；严格复现保留不同检查器合同。

调用方冻结的单命令和显式多条件测量不论是否带模型，都复用共同所有者，原cwd/argv/环境合同不变；每个字面初始条件只授权caller执行一次，模型后续提案不自动获批。相容条件可共享经回执核对的环境准备。这不是可写源挂载或OS沙箱。固定测量与CodeTask共用外部基线冻结快照，实施审批绑定已核实观察，不虚构准备血缘或新进程账目；研究驱动的CodeTask经既有专业交接直接消费已接受设计，不由协调层摘要代替，科学条件的源码角色仍归冻结执行合同。带产生来源的基线导入、分阶段/实质合同修订及剩余公开创建仍待迁移。

精确CodeTask与平直正式测量合同可以共存。准备保存两种声明，原生审批绑定科学合同；来源所有者核实际独立validator后才允许测量。项目argv投射归CodeTask环境所有者，执行与来源核查共用，不在CLI重写。独立验证不要求科学产物已经存在，整项目/API门保留，正式测量另核runtime schema。Greenfield规划读取正式入口/指标，不能把validator当实验。报告只接收所选代码血缘的实际测量；缺测义务跨报告反馈保留，无关旧候选的产物不成为当前报告依赖。成果复用读取已交付正式argv模板，不复用已完成进程的物理输出目录或额度。

已验证候选的原文件持续锁定。测量可显式声明新增的候选相对`workspace_outputs`，审批绑定精确路径和库存，实际进程回执保存输出hash。未声明新增、改动既有输入或产物、新源码/依赖都不能继承验证。交付和反馈使用同一规则：派生数据可保留、复制，但不是新验证源码；再次测量须先对反馈候选的完整库存重新独立验证。连续产物优先使用attempt隔离的`{output_dir}`，不能把已有候选文件重写为“新增输出”。声明缺失须披露为partial，单独最终交付也不能漏报。可交付已登记领域产物，不开放任意内部观察或账本。

- [CLI 分发](../src/simple_ar/cli/main.py)与[start 输入适配](../src/simple_ar/cli/start.py)。
- [原生任务应用](../src/simple_ar/app/tool_application.py)与[公共工具入口](../src/simple_ar/tools/gateway.py)。
- [结构化研究应用](../src/simple_ar/app/research_application.py)与[任务计划](../src/simple_ar/research/task_plan.py)。

历史读取与可继续执行的结构化会话必须区别对待。

## 改动应该放在哪里

| 需要修改 | 首选归属 | 避免 |
| --- | --- | --- |
| 用户参数和默认值 | CLI、已有配置解析器 | 多个入口各维护一份字段转换 |
| 下一步行动与反馈 | app | 领域模块另建调度和任务状态 |
| 来源获取、原文选择 | research | 每个报告入口复制检索逻辑 |
| 创建、修改和验证代码 | code_task / 对应工具 | 用任务名称硬编码专业能力 |
| 数值计算与数据图 | result_analysis、成熟计算/绘图库 | 用模型文本代替计算 |
| 正文、引用与装配 | report | 应用层再次解释、改写同一事实 |
| 网络连接与计量 | integrations、共享预算 | Writer/CodeTask 单独维护账本 |

原始资料、测量和采用稿各有其所有者。摘要是视图，不能覆盖原记录；
报告表达结果，不能创造结果。不要为临时上下文再保存一套竞争状态。

结构化科学行动选择协议与输入血缘，共同派发边界负责本地后端、有限测量预算及attempt级实施服务绑定，基线、补测、修订和显式重试不再各自维护。工作计划消费`task`、`steps`、`accepted_refs`及会话attempt/预算，不再输出无消费者的嵌套`research_task_context.v1`副本；已有保存记录不改写。实验报告扩展文献投影的来源身份，不另编号引用或再次解释来源元信息。

### 增加或调整能力

先沿一个真实消费者追踪输入、执行和输出，再选择最小修改点：

1. 在所属领域定义明确的输入、输出和失败含义。
2. 复用已有能力或工具入口，不为每个内部函数增加注册、适配和工厂。
3. 在用户、模型、文件和进程等外部边界校验；内部复用已成立的类型契约。
4. 通过现有会话与产物机制保存结果，让应用决定继续、询问或交付。
5. 覆盖真实消费者及失败/恢复边界，同批退出被替代实现。

原生工具恢复先询问已注册领域的 `can_reconcile`，它只允许进入已有工作核验；领域继续检查原请求与输出绑定，不能启动替代操作。进程与出版所有者还提供是否已经开始的事实，应用不再检查它们的回执文件名。Core 统一提交已保存的 attempt 结果；科研续接组合由应用判定，程序化调用遵循同一规则。

只审阅任务的 `review_document` 可像其他最终工作工具一样显式携带 `delivery`：推理前核对并绑定已有交付文件，检查成功后加入实际审阅产物，沿同一终态所有者提交，无须再调一次模型。`needs_revision` 强制保留未解决项并部分交付，不代表已改稿或科学认证。省略该字段仍只是检查，旧请求及恢复形状不变。

材料目录的调查由写作能力负责，不要求协调层猜文件名。它可批量调用已有 `read_file`，按需要读取后续内容，再选择实际观察过的窗口。最多六次决策、96,000 个观察字符，与任务共用预算，不代表穷尽材料。读取版本、完整响应及选定范围均保留；旧选材保留原绑定，中断未知请求不自动重发。

代码补丁与生成修复动作共用原子文件写入。文件快照负责回滚和字节核验：一个文件恢复失败不妨碍尝试恢复其余文件，恢复错误与原始失败同时保留。CodeTask直接消费core进程记录；洪泛保护与科学质量判断是领域结果，不改写物理执行事实。

完整提案纠正及已授权的技术验证/修复也归CodeTask。科研调用方提供批准、协议资产检查和共享账本，并保留返回证据，不再维护第二段修复循环。公开提案流程仍等待批准；回滚失败、受保护资产变化或复验额度不足时停止自动工作，科学测量仍单独负责。

测量到正文的证据连接归报告投影，应用只选择已接受记录。比较必须绑定这些测量，实现历史截止于实际测量的版本；后续补丁和被替代测量保留为历史，不作为当前结果的依据。资料检索使用原文片段与内存排序；已退休的持久索引接口明确拒绝写入，不修改历史库。

能力契约见[core/capabilities.py](../src/simple_ar/core/capabilities.py)；
工具声明和分发见[tools/specs.py](../src/simple_ar/tools/specs.py)、
[tools/registry.py](../src/simple_ar/tools/registry.py)。
不要仅为展示 schema 或 MCP 接口注册未实现工具。

### 权限、执行与恢复

- 模型可以建议操作，不能扩大编辑范围、网络权限或资源授权。
- 挂载原件只读；进程命令按入口要求批准。工作区和虚拟环境都不是操作系统沙箱。
- 实际命令、退出状态、日志与计量来自执行层，不用模型自报成功替代。
- 模型失败、进程失败与有效的负实验结果分别记录。
- 恢复保留原账本、失败与未知用量，不自动重放可能已有副作用的操作。
- 已由core明确确认中断的原生工具，可从实际失败结果补回缺失的失败观察；不重跑工具、不把core结果改成成功。未确认或无保存结果时仍拒绝盲重放。
- SDK故障诊断只保留安全的传输事件和异常类型；后续重定向的TLS失败不能抹去先前已发送HTTP的事实，旧未知预留不追溯释放。
- 外部 Agent 输出视为不可信输入，按已有修改、验证和产物规则接收；默认不得擅自执行。

相关实现见[权限](../src/simple_ar/tools/permissions.py)、
[进程控制](../src/simple_ar/core/process.py)和[模型连接目录](../src/simple_ar/integrations/model_profiles.py)。

## 重构与瘦身

重构的单位是**一项职责的替代与退出**，不是文件数量或单纯搬代码。
每批说明：

- 用户行为或可维护性具体改善在哪里。
- 哪个消费者改用新实现。
- 删除哪些旧分支、重复转换、模板或测试。
- 用什么证据确认权限、结果和恢复语义保持稳定。

删除前检查 import、公开命令、工具注册、配置、文档、测试和历史读取。
仍支持的新任务和有效历史续接不能因“旧代码”标签被误删。
确已无消费者的实现不要留作“以后可能有用”。

优先标准库、现有依赖，再考虑成熟新库。引库应替代实际自造职责，
同时检查许可、安装成本和格式兼容，不在旧实现外再包一层长期并养。
避免宽泛异常捕获后返回默认成功、每层重复防御、为每个条件增加配置开关。

代码生成的依赖建议只观察发行包元数据，不按领域关键词替用户选库、算法或替代数据，
也不能拿框架进程的包清单冒充另一任务解释器的环境。导入、实际运行和安装需各自的授权证据；
没有推断缺失依赖不等于环境已准备好。

## 验证改动

先运行受影响的行为，再扩大到直接消费者；发布冻结或共享接口大改时做全量。
不以测试数量代表完成，不为每个私有函数补独立测试。

```bash
uv run simple-ar-checks --list
uv run simple-ar-checks intake
uv run simple-ar-checks code-task
uv run simple-ar-checks report
uv run --extra examples simple-ar-checks all
```

| 修改范围 | 可选检查组 |
| --- | --- |
| CLI、配置、引导 | `quick`、`intake` |
| 会话、应用、恢复 | `core`、`application`，加具体受影响测试 |
| 资料与研究 | `research` |
| 代码与补丁 | `code-task`；案例另用 `code-task-examples` |
| 表格与图形 | `data` |
| 写作与装配 | `report` |
| 模型传输与计量 | `llm` |
| 真实进程与模板 | `execution`、`pipeline`（历史组名） |
| 共享边界重构、发布候选 | `all` |

分组是选定的烟测集合，不等于该领域全部覆盖。
直接选择测试可以缩短反馈周期：

```bash
uv run python -m unittest tests.test_research_config
uv run --extra examples python -m unittest discover -s tests -t .
```

完整发现使用 `-t .`，共享夹具从 `tests` 包导入。
合并重复夹具和同一行为的重复场景，但不要把互不相关行为塞进巨型测试方法。
删除测试需确认行为已退出或有保留测试覆盖，不能按行数机械删除。

CI 配置见[离线检查](../.github/workflows/ci.yml)，目前运行列出的分组和 wheel 构建，
不等于完整发现或真实 API 验收。新增共享边界时检查相关测试是否被选中。

真实任务验收另外检查最终内容、数值、图形、反馈和重建。
离线 mock、进程退出码和 PDF 编译不能单独证明科研成果质量。
昂贵模型、依赖安装和训练使用选定计算服务器，并明确调用与资源范围。

## 构建与提交

```bash
git diff --check
uv build
```

打包规则以[pyproject.toml](../pyproject.toml)为准。
wheel 包含应用源码与报告模板，不包含整份开发仓库；
不要让已安装命令依赖仓库根的 `scripts/` 或私有规划文件。

提交前确认：

- 公开入口、配置和直接消费者一致。
- 正常、失败和恢复行为有适当证据；说明未验证范围。
- 被替代代码、测试、模板和依赖已处理。
- 没有混入密钥、运行产物、缓存或私有记录。
- 文档与实际行为同步，未将未来计划写成已实现功能。

许可证尚未确定；代码贡献请先讨论。
