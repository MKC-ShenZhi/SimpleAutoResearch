# 开发指南

[English](DEVELOPMENT.md) · [开始使用](USAGE_zh.md) · [配置参考](CONFIG_REFERENCE_zh.md)

本文面向贡献者：先找到改动的归属，再验证行为与兼容性。
使用方法见[任务指南](WORKFLOWS_zh.md)，命令参数见[CLI 参考](CLI_REFERENCE_zh.md)。

## 准备开发环境

使用 Python 3.12+、Git、uv 和 ripgrep。在仓库根目录执行：

```bash
uv sync --locked --extra examples
uv run simple-ar --help
uv run simple-ar-checks --list
```

`examples` 额外依赖用于部分执行案例。模型密钥不是离线检查的前提；
真实模型调用和联网任务需另行配置与授权。
共用科研环境需要保留额外包时，可用 `uv sync --inexact --extra examples`。
不要把待处理项目的大型依赖或 benchmark 环境装进框架环境。

## 从哪里读代码

| 目录 | 职责 |
| --- | --- |
| `src/simple_ar/cli/` | 命令、输入适配、CLI 与 TOML 合并 |
| `app/` | 行动协调、继续条件、交互与恢复 |
| `core/` | 会话、产物、预算、能力契约和进程生命周期 |
| `tools/` | 可调用工具、参数契约、权限与领域能力桥接 |
| `research/` | 来源、文档、阅读、证据比较与研究契约 |
| `code_task/` | 项目调查、创建/修改、验证和有限修复 |
| `result_analysis/` | 确定性表格分析、数据图和重建包 |
| `report/` | 写作、修订、装配、引用和出版 |
| `integrations/` | 模型目录与服务连接 |
| `experiment/` | 实验执行及兼容消费者 |
| `tests/` | 自动化行为测试和共享测试支持 |
| `examples/` | 可阅读、可运行的案例 |
| `templates/report/` | 随包交付的报告模板 |
| `benchmark/` | 外部评测适配器，不代表已取得评测成绩 |

表中 `app/` 至 `experiment/` 均位于 `src/simple_ar/` 下。
运行输出放在 `runs/` 等忽略目录中，不是源码。

## 理解两类入口

普通目标、结构化 CLI 新任务和 `create_research_task` 使用同一行动主干。
结构化输入提供领域合同，不另建调度器，也不授予权限。

```text
新任务 → ToolApplication 行动循环 → OperationTools → 独立操作
显式兼容 API / 已保存的 ResearchApplication 会话
       → ResearchApplication → 类型化能力
共享   → SessionController、产物、预算与进程记录
```

修改新任务时，依次阅读 [CLI 分发](../src/simple_ar/cli/main.py)、
[start 输入适配](../src/simple_ar/cli/start.py)、
[共同研究创建](../src/simple_ar/app/research_intake.py)、
[ToolApplication](../src/simple_ar/app/tool_application.py) 和
[公共工具入口](../src/simple_ar/tools/gateway.py)。
新任务使用 `operations.v1`：调查、编辑、执行、检查与出版可独立调用，不再由隐式专业接力决定阶段顺序。
`OperationTools` 只组装工具注册，不运行另一套调度。检查负责绑定实际版本的意见，出版负责渲染与导出归属；正式交付声明稿件与所需格式。
新建默认 `tool_contracts="on_demand"`：共同文件、编辑和已授权运行工具直接可用，可选专业操作由能力目录发现并加载；调用方冻结合同的必要负责人直接呈现。普通源码工作沿共同循环推进，不强制经过准备控制器；保存的准备合同及 `outcomes` 模式仍按原呈现与可执行恢复处理。加载工具只改变呈现，不改变授权。
工程续用须由终态交付和唯一、完整的 `copy_project` 清单核对当前摘要；普通文件组不能冒充项目根。续用不继承执行权限、环境或验证器，歧义、遗漏、改版和未结算工作不能作为 `code_project` 提供。
新任务冻结 `inspection_protocol=subjects.v3`：一次调查可检查多个目标，但每个目标分别声明实际依据，独立核完整性、意见和依据版本；跨文件支持须明确绑定。调查共用任务预算并预留最终意见容量，不再另设六轮截止；决定可明确为未完成，读完目标本身不等于完成核查。未完成或失败的复查撤销旧通过、保留未解决必改，只有有效完整复审才替代旧意见。历史协议保留读取合同和回执，加载及无关配置供给不升级它们。
新检查直接供给当前输入容量能承接的整文件目标，大文件保留有界分页，显式窗口保持原请求范围。检查者无需为取得小型必查文件再请求一次模型决定，但全文供给不决定审阅意见。共同上下文选择器限制每轮呈现，完整观察和原生调用对仍保留。同一当前文件版本的累计已解码字节范围可补足目标，缺口、改版和二进制读取不能冒充完整。读取者计算的文件摘要可用于来源核对，不构成科学认证；保存的 `subjects.v1` 仍按原全文呈现恢复。

V3检查的可选来源由同一资格计算产生，供每轮工具契约与运行校验共用；来源编号、窗口编号和文件路径不能混用。无效最终响应最多纠正一次，重复失败保留未完成记录，不限制合法调查的轮次，也不放宽旧回执恢复条件。新响应仅在身份可唯一确定时补齐一个遗漏目标；显式错误或歧义仍拒绝，原响应与所有者绑定分别记录。非法证据错误指出具体编号；纠正耗尽后保留有界的未采用意见诊断及原轨迹，不能当作事实、检查通过或历史无效意见的升级。调用者的额外收尾指令须通过共同选择器的 `trailing_messages` 一起计费，不能在选材后另行追加。
共同材料解码器接纳检查保存的实际原文窗口，包括失败意见中的成功读取。支撑材料须核对原始回执及当前权限、版本和范围后才能复用，不继承目标读取或意见。复用正文作为共同上下文中的可选观察，不另建固定输入块或记忆库。
新检查冻结原始用户要求与反馈，局部检查目标单独标注，二者由共同上下文选择器计入容量。用户要求不是依据或权限，窄范围检查不能认证整个任务。历史缓存检查保留原输入合同。

新任务同时冻结 `delivery_review_protocol=task.v1`。`DeliveryReview` 负责正式交付的核查范围，在终态操作中调用已有检查者，回执绑定原始要求与反馈、授权目录、所需格式、正文及全部交付文件摘要。检查者负责调查、原文和意见，应用层保留终态及执行职责，不新增第二核查循环、账本或材料库。局部一致性通过不能证明整项任务通过。
只有核实过的完整通过意见可跨明确交付尝试复用，依据或范围变化即失效；新的操作可以复核失败或未完成意见，恢复不重放旧调用。组合回执中的实际原文沿共同材料解码器续用，协调层只接收紧凑意见。缺少该字段的历史任务保留原门槛。只读核查不是数值执行或科学质量保证。

付费核查启动前先验证实际生产结果：必要文件、执行输入版本及所需出版格式。交付不合法时保留已产出文件和诊断，不消耗内容审阅调用。当前来源按每份实际使用的输出核对最新生产者，未使用的同组文件被替换不再连带否决它；整次进程仍须成功、输出绑定完整，共同输入仍须有效。同一次执行恢复和历史版本追溯保留严格回执检查，不因此重放旧进程。
正式交付提案仍可能被审阅拒绝，审阅沿原账本保护一次后续决定的容量，供处理意见或明确交付部分成果；不授予新额度，也不保证足以完成所有修订。

保存的 `source_generation_protocol=prepared.v3` 任务保留原准备与审批后执行负责人，普通新任务不再选择这一协议。显式代码任务继续守住精确编辑、验证和执行合同。

保存的准备协议将12份可编辑源码与只读输入副本分别约束：输入最多64份显式文件，每份256,000字节，总量3,072,000字节。已有所有者按原字节复制并绑定版本，无须让模型转录数据；反馈保留输入的不可编辑身份。保存的 `prepared.v1` 及无标记准备继续使用原来的合并限制。
新 `prepared.v3` 可用完整内容或精确替换修订已绑定的可编辑原文件；完整内容须有完整当前文件观察，目录成员身份本身不足以授权整文件重写。只读输入、并发改动校验及执行审批继续约束；保存的 `prepared.v2` 仍使用原精确替换合同。
显式指定的代码范围、验证器和测量合同仍由原执行负责人约束，不能用通用操作绕过。
没有该协议的历史原生任务通过 `load`、`supply` 沿保存的专业控制恢复。新 `ToolApplication.create` 只创建 `operations.v1`，`None` 和旧专业控制选项在创建前拒绝；兼容测试加载明确保存格式，不再新建旧控制。不要修改旧任务文件强行升级。
交付不要求正式报告：普通说明和中文 Markdown 沿共同交付、反馈路径处理，按需出版；明确声明报告或请求 PDF／TeX 时继续核查意见与版本。
core 保留实际发生的事实，包括尝试、产物、资源消耗与进程结果；专业工作仍使用同一执行与记录基础。

新操作任务保存 `working.v2`。当前工作负责人通过已有 `update_work_plan.notes` 回执保存简明认识；共同选择器保留近期完整对话，并按明确引用提供较早原始观察，不再调用另一位后台摘要作者或用词面相似的历史填满余量。
原记录仍可按需读取，笔记不能证明来源、权限或科学正确性；容量缺口与来源版本变化必须可见。
保存的 `working.v1` 任务继续沿原有自动检查点、选择规则、登记产物和费用恢复，摘要失败与未知用量保持原合同，不静默改变旧任务。
同一逻辑调用已实际收到完整专业响应并成功结算时，可以保留其早先失败尝试的全部有界预留，继续采用有效成果。源码采用、当前检查回执及已接受的原生结果共用core中的费用判定；这不授权自动格式纠错、进程重放或释放未知费用。在途请求、无上界用量及未知进程仍然停止。
交付检查在生产结果登记后进行。执行已完成且字节绑定完好的结果，可以把交付缺项交回同一循环，
不重放生产步骤、不把未交付说成完成。历史回执不改，绑定损坏仍停止；实际原稿与导出清单归出版者负责。

检查者通过实际只读工具自行定位、补读来源，最后单独提交结构化意见；不要求在正文中模拟工具调用。Chat与Responses按已选连接保留原生调用、读取结果和必要推理项，最终意见和版本规则沿用原机制，部分读取与失败响应仍保留。出版检查、预览共用绑定实际字节的PDF信息，提前核剩余物理进程次数，实际计费仍归core；顺序进程的超时之和是上界，不能当作最低耗时拒绝正常任务。

新原生任务展示工作区工具和获授权的能力目录，`load_tools` 经同一注册器
加载下一步需要的契约。契约展示选项与确切默认值见
[配置参考](CONFIG_REFERENCE_zh.md)，不为此另建派发路径。

兼容边界仍然存在。显式 `create_session` 和 `ResearchApplication.create`
消费者保留原返回类型与续接合同，见
[ResearchApplication](../src/simple_ar/app/research_application.py)。
已保存会话按记录的所有者和策略恢复；只读 legacy v1 记录与仍可执行的
ResearchApplication 会话不同。旧八阶段执行器已不再由 `run`、`resume`、
`research-code-task` 或 `research-experiment` 启动，这不表示
ResearchApplication 已被删除。`research-brief` 仍是 `research-session`
的简报兼容名称。不支持的新声明在创建前报错，不静默回退到兼容执行。

输入补齐、审批和续接遵循 [CLI 恢复合同](CLI_REFERENCE_zh.md#原生任务恢复)。
补充输入或额度时保留已保存合同、先前观察与费用，不把历史任务静默迁移到新默认值。

## 改动应该放在哪里

| 需要修改 | 首选归属 | 避免 |
| --- | --- | --- |
| 用户参数和默认值 | CLI、已有配置解析器 | 多个入口各维护一份字段转换 |
| 跨领域下一步行动与反馈 | app | 第二套全局调度和任务状态 |
| 来源获取、原文选择 | research | 每个报告入口复制检索逻辑 |
| 创建、修改和验证代码 | code_task / 对应工具 | 用任务名称硬编码专业能力 |
| 数值计算与数据图 | result_analysis、成熟计算/绘图库 | 用模型文本代替计算 |
| 正文、引用与装配 | report | 应用层再次解释、改写同一事实 |
| 网络连接与计量 | integrations、共享预算 | Writer/CodeTask 单独维护账本 |

原始资料、测量和采用稿各有其所有者。摘要是原记录的视图，报告表达结果而非创造结果。
行动状态归应用，执行事实归共享账本；专业内部模型调用、重试与工作使用同一计量，
不增加平行任务状态、费用计数器或全局调度器。

新原生任务使用 `available_operations.v1`：在实际预算、尝试数和审批限制内保留可用操作，
不强制最后一次可负担决策只能终结任务，允许保留有用的中间工作。
只有显式且校验通过的交付才完成请求；耗尽保留工作，不宣告成功。
工具执行时为上层下一次决定保留预估容量，显式终结批次、可直接交付的负责人和调用方接管除外。
检查者取材时另保留最终意见的容量，嵌套保护沿同一账本叠加。预估不能预知后续原文增长，
尤其在不设输出上限时不能保证完成；未知用量不能被解释为新增可用容量。
有保守上界的未知费用仍全额占用原预留，但不等于可用容量完全未知；检查者自身未确认的响应
或来源执行仍不得采用，不能用这个区分放行未完成的检查。
连接切换和显式额度授权共用本地操作关闭的证明，覆盖专业模型调用，但不据此采用成果或核销费用。
显式新额度保留旧条目，资源准入看当前额度，用量展示仍报告全部历史未知；在途、未接纳的操作
和未确认进程不能越过该边界。
新出版物的审批清单覆盖可能使用的图片，现有渲染器将实际排版依赖保存在按字节绑定的导出清单中。
恢复、检查和交付核这些依赖及生产者；历史清单保留原语义。未引用预览的变化不应阻断新稿，
也不能成为接受过时实际图表的理由。这不等于科学附件来源已经得到证明。
历史 `protected_decision.v1`、`closing_decision.v2` 和无策略任务保留已保存行为。
策略细节见[预算所有者](../src/simple_ar/core/budget.py)和[配置参考](CONFIG_REFERENCE_zh.md)。

### 增加或调整能力

沿一个真实消费者追踪输入、执行和输出：

1. 在所属领域定义输入、输出和失败含义。
2. 复用已有能力或工具边界，只注册已实现操作。
3. 在用户、模型、文件和进程边界校验，内部复用类型契约。
4. 通过现有会话与产物机制保存结果，向应用返回证据。
5. 覆盖直接消费者及失败/恢复行为，同批退出被替代实现。

从[能力契约](../src/simple_ar/core/capabilities.py)、
[工具声明](../src/simple_ar/tools/specs.py)和
[注册器](../src/simple_ar/tools/registry.py)开始。
专业内部可有必要的有界工作循环，但不得另建全局任务运行时、审批机制或账本。

### 材料与候选归属

只读材料与可编辑项目分开。准备产生候选；可运行提案仍不代表执行授权或成功证据。
执行消费已登记的准备回执，以及获批准的命令、环境、输入版本和预期输出。
反馈产生新候选并保留原版本。

验证、物理执行与科学测量回答不同问题。CodeTask 负责技术验证与有限修复，
research 负责测量协议，报告投影把已接受测量连接到实际测量的代码版本。
验证器通过、引用标记正确或报告编译成功都不证明科研质量；
后续补丁和被替代测量保留为历史。

交付绑定已登记产物及实际字节。源码、依赖或输入变化使复用失效，
生成数据不会自动成为已验证源码。缺少必需输出和未解决的审阅问题必须在部分交付中披露。
编辑与回滚复用工作区快照和原子写入，恢复失败与原错误同时保留。

准备、执行和输出的确切参数见[配置参考](CONFIG_REFERENCE_zh.md)与
[CLI 合同](CLI_REFERENCE_zh.md)；实现细节沿
[CodeTask 所有者](../src/simple_ar/code_task/)和
[报告所有者](../src/simple_ar/report/)阅读。

### 权限、执行与恢复

- 模型可建议行动，不能扩大编辑范围、网络权限或资源授权。
- 挂载原件只读。协议接受与进程审批是不同授权；调用方初始授权不自动批准模型后续提案。
- 工作区和虚拟环境不是操作系统沙箱；外部 Agent 输出视为不可信输入。
- 命令、退出状态、日志和用量来自执行层。区分模型失败、进程失败与有效的负实验结果。
- 恢复保留预约、失败与未知用量；后续传输错误不能证明先前请求从未发送。
- 经领域所有者核验保留结果，不盲目重放可能已有副作用的操作。core 确认的中断可补回缺失失败观察，不重跑，也不把失败改成成功。
- 输入补齐保留旧费用，每项获授权额度只生效一次；补齐中断须先核对才能继续工作。

参见[会话控制](../src/simple_ar/core/session.py)、
[产物](../src/simple_ar/core/artifacts.py)、
[权限](../src/simple_ar/tools/permissions.py)、
[进程控制](../src/simple_ar/core/process.py)和
[模型目录](../src/simple_ar/integrations/model_profiles.py)。

可信 Python 使用宿主进程的操作系统权限；受限宿主服务和权限声明**不是沙箱**，

最后决策只提供当前已可见且适合直接结束的工具。生产者不必实现续行才能被唯一
可信消费者承接；通用停止绑定原回执，仍走同一账本与恢复。
具体用法见[扩展指南](LOCAL_EXTENSIONS.md#optional-explicit-completion)。

[扩展测试](../tests/test_local_extensions.py)；扩展指南包含定向验证命令和恢复限制。

## 重构与瘦身

重构的单位是**一项职责的替代与退出**，不是文件数量或单纯搬代码。
每批说明：

- 用户行为或可维护性具体改善在哪里。
- 哪个消费者改用新实现。
- 删除哪些旧分支、重复转换、模板或测试。
- 用什么证据确认权限、结果和恢复语义保持稳定。

删除前检查 import、公开命令、工具注册、配置、文档、测试和历史读取。
仍支持的新任务和有效历史续接不能因“旧代码”标签被误删。
确已无消费者的实现不要留作“以后可能有用”。

优先标准库、现有依赖，再考虑成熟新库。引库应替代实际自造职责，
同时检查许可、安装成本和格式兼容，不在旧实现外再包一层长期并养。
避免宽泛异常捕获后返回默认成功、每层重复防御、为每个条件增加配置开关。

代码生成的依赖建议只观察发行包元数据，不按领域关键词替用户选库、算法或替代数据，
也不能拿框架进程的包清单冒充另一任务解释器的环境。导入、实际运行和安装需各自的授权证据；
没有推断缺失依赖不等于环境已准备好。

## 验证改动

先运行受影响的行为，再扩大到直接消费者；发布冻结或共享接口大改时做全量。
不以测试数量代表完成，不为每个私有函数补独立测试。

```bash
uv run simple-ar-checks --list
uv run simple-ar-checks intake
uv run simple-ar-checks code-task
uv run simple-ar-checks report
uv run --extra examples simple-ar-checks all
```

| 修改范围 | 可选检查组 |
| --- | --- |
| CLI、配置、引导 | `quick`、`intake` |
| 会话、应用、恢复 | `core`、`application`，加具体受影响测试 |
| 资料与研究 | `research` |
| 代码与补丁 | `code-task`；案例另用 `code-task-examples` |
| 表格与图形 | `data` |
| 写作与装配 | `report` |
| 模型传输与计量 | `llm` |
| 真实进程与模板 | `execution`、`pipeline`（历史组名） |
| 共享边界重构、发布候选 | `all` |

分组是选定的烟测集合，不等于该领域全部覆盖。
直接选择测试可以缩短反馈周期：

```bash
uv run python -m unittest tests.test_research_config
uv run --extra examples python -m unittest discover -s tests -t .
```

完整发现使用 `-t .`，共享夹具从 `tests` 包导入。
合并重复夹具和同一行为的重复场景，但不要把互不相关行为塞进巨型测试方法。
删除测试需确认行为已退出或有保留测试覆盖，不能按行数机械删除。

[CI 配置](../.github/workflows/ci.yml)定义分组离线检查和 wheel 构建，不等于完整发现或真实 API 验收；仓库端是否启用自动执行另由维护者管理。
新增共享边界时检查相关测试是否被选中，不因文档更新擅自启用工作流。

真实任务验收另外检查最终内容、数值、图形、反馈和重建。
离线 mock、进程退出码和 PDF 编译不能单独证明科研成果质量。
昂贵模型、依赖安装和训练使用选定计算服务器，并明确调用与资源范围。

## 构建与提交

```bash
git diff --check
uv build
```

打包规则以[pyproject.toml](../pyproject.toml)为准。
wheel 包含应用源码与报告模板，不包含整份开发仓库；
不要让已安装命令依赖仓库根的 `scripts/` 或私有规划文件。

提交前确认：

- 公开入口、配置和直接消费者一致。
- 正常、失败和恢复行为有适当证据；说明未验证范围。
- 被替代代码、测试、模板和依赖已处理。
- 没有混入密钥、运行产物、缓存或私有记录。
- 文档与实际行为同步，未将未来计划写成已实现功能。

许可证尚未确定；代码贡献请先讨论。
